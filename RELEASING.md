# Publishing an in-app update

Pasteback 0.2.0+ embeds Sparkle 2.10.0. The app reads the signed `appcast.xml` on main and installs signed archives from GitHub Releases. 0.1.x users must install 0.2.0+ manually once.

1. Implement and verify the change. Increment MARKETING_VERSION and CURRENT_PROJECT_VERSION in both target configurations. Build numbers must increase monotonically.
2. Run `bash scripts/package.sh`. Check universal architectures, signatures and versions. Current builds are ad-hoc signed testing builds; Developer ID signing and notarization are still needed for polished public distribution.
3. Run `SPARKLE_BIN=/path/to/Sparkle/bin bash scripts/prepare-update.sh`. The official Sparkle tools are available from the pinned 2.10.0 distribution or Xcode package artifacts. The script signs the ZIP and feed using the `Pasteback` account in the current Mac login Keychain. Never regenerate or upload the private key. Preserve the key when moving to a different Mac; losing it without Developer ID key rotation support strands existing clients.
4. Commit and push tested source (including Package.resolved). Publish the matching stable release/tag with DMG, ZIP and SHA256SUMS.txt. Do not upload private keys, user data or Build/ to source control.
5. Only after the release downloads are public and verified, publish the generated appcast.xml to repository main. Use the generated bytes unchanged: editing signed XML after generation invalidates the feed signature. Keep the feed URL and SUPublicEDKey stable.
6. From a previous installed version, click Check for Updates, install and relaunch. Verify the new bundle version and preserved history. Also verify latest-version and offline error dialogs.

The updater never needs a GitHub token. Installation is user initiated; background polling, system profiling and silent installation are disabled. Running from the DMG is not supported for self-update; install to Applications first.
